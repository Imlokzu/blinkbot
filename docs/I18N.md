# Localization (i18n) Guide

This repository has a strict language policy: all identifiers, types, file names, docs, and code comments are **English**. All user-visible text is maintained in locale files, primarily in **Ukrainian**, with an English fallback.

There are three localization catalogs in the repo:

1. **Screen (`Virtual Bot/static/screen/i18n.js`)**
   A plain JS file exporting a `DICT` object. Used by calling `t("key")` in JS or via `data-i18n="key"` in HTML.
2. **Dashboard (`Virtual Bot/dashboard/src/lib/i18n.ts` and `Virtual Bot/dashboard/src/locales/*.ts`)**
   React/TS dashboard translation strings. These files contain a `uk` object and an `en` object of type `Record<keyof typeof uk, string>`.
3. **Integrations (`Virtual Bot/integrations/locales.py`)**
   Python dictionaries used when standard integrations (e.g., Telegram) message the user.

## Adding Strings and Placeholders

When adding a new string, use the `area.thing` format for keys (e.g., `composer.placeholder` or `timer.head`).
If a string needs a variable, use `{name}` placeholders in both languages.

Example:
```ts
// Dashboard locale
const uk = {
  'sessions.daysAgo': '{count} дн тому',
};
const en: Record<keyof typeof uk, string> = {
  'sessions.daysAgo': '{count} days ago',
};
```

## Adding a New Language

1. Add the language code to the respective language array or type (e.g., in `LANGS` in `Virtual Bot/static/screen/i18n.js`).
2. Add a full object dictionary matching the exact keys as the existing `uk` locale in the relevant catalog.

## Managing Debt

`python scripts/i18n_check.py debt` shows the current debt per file. On 2026-09-27 it counted 6577 lines of Ukrainian comments and docstrings and 2960 lines of hard-coded Ukrainian strings in 280 files (every line of a multi-line docstring counts, which is why this is higher than the 3220 in `AGENTS.md`).

**When you touch a file:**
1. Translate the Ukrainian comments in that file to English.
2. Extract the hardcoded user-visible text to the appropriate locale catalog and use the key reference instead.

## Checker and Ratchet

We have tooling to stop translation debt from growing and to verify catalog completeness.

### CI Enforcement
CI runs `.github/workflows/i18n.yml` to automatically verify standard i18n checks. If you increase the amount of debt or misconfigure catalogs, CI will fail.

### Running the Checker
You can manually run the checker script from the repository root:
```bash
python scripts/i18n_check.py all
```
This ensures key parity across languages, correct `{placeholder}` matching, and that no unkeyed hardcoded Cyrillic was added to code files.

### Known limits of the scanner
- **Python**: Docstrings are reliably found via AST traversal. However, any floating strings assigned to variables will not be detected as docstrings.
- **JS / TS / HTML**: It relies on a regex token scanner. Complex nested RegExp literals containing `//` or `/*` could potentially confuse the comment state.
- **Bash (.sh)**: Checks only `#` comments for cyrillic and does not scan string literals.

### Refreshing the Baseline
If you reduce debt (e.g., translated comments to English or moved hardcoded strings to catalogs), you must update the baseline so the ratchet captures your progress:
```bash
python scripts/i18n_check.py ratchet --update
```
Commit the updated `scripts/i18n-debt-baseline.json` with your PR.

The counter reads files from disk, so run `--update` on a tree that holds only your change. Uncommitted work from another session in the same checkout would otherwise be written into the baseline. The count is the same on Python 3.9 through 3.14; CI uses 3.12.
